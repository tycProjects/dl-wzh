# Инструкция по запуску

## 1. Backend и админ-панель

Требуется Node.js 18+. Внешние npm-пакеты не нужны.

```bash
cd backend
cp .env.example .env        # заполните значения
node --env-file=.env src/server.js
```

Сервер слушает `PORT` (по умолчанию 8080). Админ-панель: `http://localhost:8080/admin/`.

Локальная проверка без Telegram (только для разработки):
```bash
DEV_AUTH=1 OWNER_EMAIL=dev873295@gmail.com node src/server.js
```
На экране входа появится поле для email. Не включайте `DEV_AUTH` в продакшене.

## 2. Настройка входа через Telegram

1. В Telegram откройте @BotFather, отправьте `/newbot`, задайте имя и username бота (например, `DroidStoreBot`).
2. Токен, который выдаст BotFather, положите в `backend/.env` как `TELEGRAM_BOT_TOKEN`. Никому его не передавайте.
3. Укажите в `.env`:
   - `TELEGRAM_BOT_USERNAME` — username бота без @;
   - `TELEGRAM_WEBHOOK_SECRET` — случайная строка (например, 32 символа из `openssl rand -hex 16`);
   - `PUBLIC_URL` — публичный https-адрес сервера (для теста локально используйте туннель, например cloudflared или ngrok);
   - `OWNER_TELEGRAM_ID` — ваш числовой Telegram ID (узнать его можно у бота @userinfobot).
4. Запустите backend. При старте он сам зарегистрирует webhook в Telegram.

Аккаунт создаётся автоматически при первом входе. Отдельной регистрации нет.

## 3. Роли

| Роль | Права |
|---|---|
| user | просмотр каталога, скачивание, оценки, жалобы |
| developer | создание студий и приложений (выдаётся автоматически при создании студии) |
| moderator | очередь модерации, жалобы |
| admin | блокировка пользователей, отметки Official / Featured / Security Checked, галочки студий, журнал |
| owner | назначение ролей admin и moderator, полный журнал, управление ролями |

Роль owner назначается только через `OWNER_EMAIL`, через API её назначить нельзя. Администраторы не могут менять роли и блокировать пользователей равного или более высокого уровня.

## 4. Жизненный цикл приложения

1. Разработчик создаёт студию (`POST /api/studios`).
2. Создаёт приложение (`POST /api/studios/:id/apps`) со статусом `draft`.
3. Загружает APK (`POST /api/apps/:id/versions?versionCode=&versionName=`), иконку и скриншоты (`POST /api/images?kind=icon|screenshot`), затем привязывает их через `PATCH /api/apps/:id`.
4. Отправляет на модерацию (`POST /api/apps/:id/submit`). Запускается проверка безопасности, статус становится `pending_review`.
5. Модератор одобряет или отклоняет. Публикацию запускает `publish`. Скачивание доступно только для статуса `published`.

## 5. Проверка безопасности: что реально выполняется

- SHA-256 файла: выполняется всегда.
- Проверка структуры APK (ZIP и наличие `AndroidManifest.xml`): выполняется.
- VirusTotal: выполняется, если задан `VIRUSTOTAL_API_KEY`. Без ключа статус `unknown`.
- Отсутствие обнаружений не даёт статус «безопасно»: максимум `needs_review`.
- Не реализовано: проверка цифровой подписи (нужен `apksigner`), извлечение разрешений из бинарного манифеста (нужен `aapt2`), поведенческий анализ. Эти ограничения возвращаются в поле `security.limitations`.

## 6. База данных

Текущая версия хранит данные в `backend/data/db.json`. Это подходит для разработки. Для продакшена перенесите модель на PostgreSQL по `database/schema.sql` и замените слой хранения. Папки `backend/data/` нет в репозитории.

## 7. Android-приложение

Gradle Wrapper: `gradle wrapper --gradle-version 8.11.1` (нужен установленный Gradle). Затем `./gradlew assembleDebug`.

Экраны студии, загрузки и оценок в Android-клиенте пока не реализованы. Сейчас клиент показывает только каркас. Серверные API уже готовы для их подключения.

## 8. Настройка Android-клиента (реализовано)

В `gradle.properties` (локально, не коммитится) задайте:
- `DS_API_BASE_URL` — адрес backend. Эмулятор: `http://10.0.2.2:8080` (по умолчанию). Телефон в той же сети: `http://IP_вашего_ПК:8080`.
Вход в приложении идёт через бота: приложение открывает Telegram, вы нажимаете Start, и вход подтверждается автоматически.

Что есть в приложении:
- Вход через Telegram-бота. Токен хранится в EncryptedSharedPreferences.
- Каталог с поиском, сортировкой (популярные, рейтинг, новые) и анимированным появлением карточек.
- Карточка приложения: скриншоты, описание, бейджи с пояснениями по нажатию, блок безопасности (Unknown, если проверки не было), оценки, скачивание через DownloadManager, жалоба на мошенничество.
- DroidStore Studio: создание студии, список приложений со статусами, редактор с выбором APK, иконки и до 10 скриншотов, отправка на модерацию.
- Профиль с ролью и выходом.

Проверка перед релизом: откройте проект в Android Studio, выполните Gradle Sync и `./gradlew assembleDebug`. В этой среде сборка Android не выполнялась (нет доступа к Maven и Gradle), поэтому первый запуск может выявить мелкие ошибки компиляции, которые нужно поправить по сообщениям Android Studio.
